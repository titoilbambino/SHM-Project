# 004 — Training on every eligible strain sample

Does training the [001 temporal convolutional network](001.ipynb) on every eligible endpoint improve estimation of `SB01_x` on held-out recordings?

| | Training stride at 100 Hz | Endpoints in final fit | Batch size | Updates per final-fit epoch |
|---|---:|---:|---:|---:|
| 001, saved CUDA run | 125 samples (1.25 s) | 1,980 | 32 | 62 |
| 004, dense training on MPS | 1 sample (0.01 s) | 247,118 | 512 | 483 |

Each example contains 500 samples of the 75 acceleration channels and one target at the last sample. Training uses the same 41.5 minutes in both experiments. The dense windows overlap by 499 samples. This comparison changes the training stride, batch size and checkpoint selection frequency.

A short synthetic MPS benchmark of the same TCN gave 2.7k, 8.0k, 10.0k and 11.4k windows/s at batch sizes 32, 128, 256 and 512, respectively. Batch size was selected on throughput.

## Fitting and evaluation

Use the [001 forward split and recording pairs](001.md). On the four undamaged `_02` sweeps, hold out one whole recording per validation fold. Subtract fit-recording channel means and fit the 001 residual TCN with Adam (0.001) and MSE. Each pass shuffles all eligible fit endpoints without replacement.

Evaluate MSE on the full validation grid eight times per pass, including the last batch. Checkpoints are eligible from the end of the first pass. Stop after 20 consecutive checks without a lower eligible MSE (2.5 passes), or at 200 passes. Restore the best eligible weights. Express each fold’s best update as a fraction of its training pass. As in 001, round the median best pass to the nearest integer for the final fit on all four recordings. [Configuration](../configs/004.yaml)

Score validation and the four paired `_01` test recordings at the original endpoints (zero-based indices 499, 624, 749, … within each recording). Compare RMSE (MPa) and R² per recording and their unweighted means. Report optimizer updates at the selected epoch.

## Running

The [experiment script](../experiments/dense_stride_004.py) uses Keras with the PyTorch backend on MPS. From the repository root, use a Python environment with the dependencies in `requirements.txt`.

```sh
python -m experiments.dense_stride_004 --config configs/004.yaml --data /path/to/data_100Hz.h5
```

`--check-data` checks the recording layout and endpoint counts without fitting. Each run writes its resolved settings, fold histories and test scores to a new directory under `results/004/`.
